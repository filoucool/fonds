# Archive format v1

An archive directory is a self-contained Phase 1 repository archive. `schemaVersion` is `1`. `storage.relativeLayout` is `v1`. This build reads and writes version 1 only.

The directory is stored on a pool at `archives/<2 hex>/<id>/`. Paths recorded inside the format are relative to that directory. The catalog id is the directory name `<id>`, a stable repository UUID. The directory can be copied, checksum-verified, and registered on another machine without the original SQLite catalog.

## Directory

```text
<id>/
  repository.git/     bare git, not a mirror clone
  archive.json
  checksums.json
  metadata/
  releases/
  lfs/objects/
  wiki/wiki.git/
  submodules/
  sync-records/
```

`repository.git` is the preserved bare repository: current refs plus `refs/archive/keep` and `refs/archive/history`. See the ref model in [Architecture](../architecture/overview.md).

`wiki/wiki.git` is a bare git directory. Other bare git directories in the archive, including any under `submodules/`, follow the same checksum rule as `repository.git`: they are omitted from `checksums.json` and checked with `git fsck`.

`metadata/`, `releases/`, `lfs/objects/`, `submodules/`, and `sync-records/` are part of relative layout `v1`. Files under `sync-records/` contain no tokens. Issue, pull request, discussion, and release text is stored as a `.md` file and a sibling `.html` file. `lfs/index.json` lists every LFS pointer found in the tree. Component state in `archive.json` is the record of each component. A disabled profile component is `skipped` and is never reported as success.

## archive.json

`archive.json` is the manifest. It has these fields:

| Field | Value |
| --- | --- |
| `schemaVersion` | `1` |
| `id` | Stable repository UUID. Matches the directory name. |
| `createdAt` | Time the archive record was created. |
| `updatedAt` | Time the manifest was last updated. |
| `generation` | Generation. Part of the canonical manifest hashed into `contentHash`. |
| `contentHash` | sha256 of the canonical manifest with this field removed. |
| `source.canonicalUrl` | Canonical source URL. |
| `source.identityKey` | Identity compared during rebuild conflict checks. |
| `source.provider` | Provider: generic git, GitHub, or GitLab. |
| `source.providerRepoId` | Provider repository id. |
| `source.aliases` | Aliases for the source. |
| `source.defaultBranch` | Default branch. |
| `displayName` | Display name. `POST purge` requires this string to be typed back. |
| `description` | Description. |
| `license` | License. |
| `profile.name` | Profile name. |
| `profile.components` | Components selected by the profile. |
| `components` | Map of component name to component state. |
| `refs.current` | Current upstream view. |
| `refs.archived` | Archival keep and history refs. |
| `storage.relativeLayout` | `v1` |

`refs.current` is the published upstream view: `refs/heads`, `refs/tags`, `refs/notes`, and optional `refs/pull` or `refs/merge-requests`. `refs.archived` is `refs/archive/keep/<oid>` and `refs/archive/history/<namespace>/<ref>/<timestamp>-<oid>`. Verify resolves the object ids named in the manifest.

### Component states

Each value in `components` is one of:

`complete`, `partial`, `failed`, `unsupported`, `skipped`, `pending`, `running`, `paused`.

A component the profile disables is `skipped`. A skipped component is never reported as success. Generic git marks platform-only components `unsupported`.

### contentHash

`contentHash` is the sha256 of the canonical JSON serialization of `archive.json` with object keys sorted and the `contentHash` field removed.

`contentHash` covers the manifest. File bytes are hashed in `checksums.json`. Bare git object stores are checked with `git fsck`.

## checksums.json

`checksums.json` has these fields:

| Field | Value |
| --- | --- |
| `schemaVersion` | `1` |
| `algorithm` | `sha256` |
| `generatedAt` | Time this checksum file was produced. |
| `files` | Array of entries. |

Each entry in `files`:

| Field | Value |
| --- | --- |
| `path` | Archive-relative path, forward slashes. |
| `sha256` | sha256 digest of that path's checksum input. |
| `bytes` | Size recorded for the entry. |
| `kind` | Kind of filesystem entry the writer hashed. |

Path rules:

- Paths are relative to the archive directory and use forward slashes.
- No absolute machine path appears in `checksums.json` or in `archive.json`.
- `checksums.json` does not list itself.
- `repository.git`, `wiki/wiki.git`, and every other bare git directory are omitted. Those directories are verified with `git fsck`, not with a file-by-file hash of the object store.
- A symlink is hashed as the link text. The walk does not follow the link, including a link that points outside the archive.

Replacement of `checksums.json` is a temp file in the archive directory, then `fsync`, then `rename` over `checksums.json`. A crash during the write leaves the previous `checksums.json` in place.

## Credentials and host paths

`archive.json` and `checksums.json` contain neither credentials nor absolute machine paths. Sync records and export manifests follow the same rule for tokens. Provider tokens stay in the SQLite catalog. A catalog backup contains them; an archive directory does not.

## Version compatibility

Readers in this build accept `schemaVersion` 1 only.

- A higher `schemaVersion` is refused for mutation. The process does not update that directory.
- Rebuild reports any version other than 1 and skips that directory. It does not overwrite the directory and it does not register it.
- An application upgrade does not rewrite an existing archive into a new format in place.

Import (`POST /api/catalog/import-local`) accepts a directory path that contains `archive.json`, verifies `checksums.json` before registering, and leaves the source path in place. The import path is how a version 1 directory moves between machines without the original catalog. Details are in [Backup and recovery](../operations/backup-recovery.md).
